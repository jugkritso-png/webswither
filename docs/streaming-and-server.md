# การสตรีมและ Stream Gateway

สตรีมหลายปลายทาง, ติดตั้ง Gateway บนเซิร์ฟเวอร์, ผู้ใช้หลายคน, หน้าผู้ดูแล และ SRT / NDI — กลับไปที่ [README](../README.md)

## สตรีมสด (RTMP) — หลายช่องทางพร้อมกัน

เบราว์เซอร์ส่ง RTMP เองไม่ได้ จึงต้องมี **Stream Gateway** เล็ก ๆ คั่นกลาง:

```
เบราว์เซอร์ ──(WebSocket ครั้งเดียว)──▶ Gateway: FFmpeg เข้ารหัส H.264/AAC ครั้งเดียว
                                          ├──▶ YouTube
                                          ├──▶ Facebook
                                          └──▶ Twitch / RTMP อื่น ๆ
```

- อินเทอร์เน็ตขาขึ้นของเครื่องที่เปิด WebMix ใช้เท่ากับสตรีมช่องเดียว ไม่ว่าจะส่งกี่ปลายทาง
  (Gateway ต้องมีขาขึ้นพอสำหรับทุกปลายทาง เช่น 3 ปลายทาง × 4.5 Mbps ≈ 14 Mbps)
- แต่ละปลายทางเริ่ม/หยุดได้อิสระระหว่างไลฟ์ ปลายทางที่หลุดจะเชื่อมต่อใหม่เองทุก 5 วินาที โดยไม่กระทบช่องอื่น
- จำนวนปลายทางสูงสุดต่อการเชื่อมต่อตั้งได้ด้วยตัวแปร `MAX_DESTINATIONS` (ค่าเริ่มต้น 6)

### ติดตั้ง Gateway บนเซิร์ฟเวอร์ด้วยคำสั่งเดียว (แนะนำ)

ต้องมี VPS ที่ใช้ **Ubuntu 22.04 / 24.04** หรือ **Debian 12** (เช่น DigitalOcean, Vultr, Linode, AWS Lightsail, Google Cloud)

| ใช้งาน | CPU / RAM ขั้นต่ำ |
|---|---|
| 720p30 | 2 vCPU / 2 GB |
| 1080p30 – 1080p60 | 4 vCPU / 4 GB |
| 1440p / 4K30 | 8 vCPU / 8 GB ขึ้นไป (หรือเครื่องที่มีการ์ดจอ NVIDIA) |
| 4K60 | 16 vCPU หรือการ์ดจอ NVIDIA |

ระหว่างไลฟ์ แถบสถานะ STREAM จะแสดงความเร็วการเข้ารหัสของ Gateway (`ENC 1.00x`)
ถ้าต่ำกว่า 1.00x แปลว่าเซิร์ฟเวอร์ไม่แรงพอ ให้ลดความละเอียด/เฟรมเรต หรือใช้เซิร์ฟเวอร์ที่แรงขึ้น

เซิร์ฟเวอร์ที่มีการ์ดจอ NVIDIA (ติดตั้ง NVIDIA Container Toolkit แล้ว) ใช้การ์ดจอเข้ารหัสได้ด้วย `VIDEO_ENCODER=h264_nvenc`
(ถ้ารันแบบ Docker ต้องเพิ่ม `gpus: all` ให้ service `gateway` ใน `docker-compose.yml` ด้วย)

1. เปิดพอร์ตในไฟร์วอลล์ของผู้ให้บริการ (Security Group / Firewall rules):
   - TCP **80, 443** — หน้าเว็บ/HTTPS/WebSocket
   - TCP+UDP **3478** และ UDP **49160–49250** — TURN สำหรับกล้องมือถือ
   - UDP **9000–9009** — รับสัญญาณ SRT
2. SSH เข้าเซิร์ฟเวอร์แล้วรัน:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/jugkritso-png/webswither/HEAD/server/deploy/install.sh | sudo bash
   ```

3. เมื่อเสร็จ สคริปต์จะแสดงค่า `wss://…/?token=…` — นำไปใส่ช่อง **Stream Gateway** ใน WebMix
   (ปุ่มตั้งค่า → แท็บการสตรีม) แล้วกด STREAM ได้เลย

สคริปต์จะติดตั้ง Docker, สร้างรหัสลับ (token) แบบสุ่ม และใช้ **Caddy** ขอใบรับรอง HTTPS ให้อัตโนมัติ
ถ้าไม่มีโดเมน จะใช้ `<IP>.sslip.io` ให้เอง ถ้ามีโดเมนของตัวเอง ให้ชี้ A record มาที่ IP ของเซิร์ฟเวอร์แล้วรัน:

```bash
curl -fsSL https://raw.githubusercontent.com/jugkritso-png/webswither/HEAD/server/deploy/install.sh | sudo DOMAIN=live.example.com bash
```

การดูแลหลังติดตั้ง (ไฟล์อยู่ที่ `/opt/webmix-gateway/server/deploy`):

| ต้องการ | คำสั่ง |
|---|---|
| ดูค่า Gateway URL อีกครั้ง | `sudo cat /opt/webmix-gateway/server/deploy/gateway-url.txt` |
| ตรวจสถานะ | เปิด `https://โดเมน/` ในเบราว์เซอร์ ต้องเห็น `WebMix Stream Gateway: OK` |
| ดู log | `cd /opt/webmix-gateway/server/deploy && sudo docker compose logs -f gateway` |
| อัปเดตเป็นเวอร์ชันล่าสุด | รันคำสั่งติดตั้งเดิมซ้ำ (token และโดเมนเดิมยังอยู่) |
| เปลี่ยน token | ลบบรรทัด `STREAM_TOKEN=` ใน `.env` แล้วรันคำสั่งติดตั้งซ้ำ |
| เปิดพอร์ต UDP สำหรับรับ SRT เพิ่ม | รันคำสั่งติดตั้งซ้ำโดยใส่ `SRT_PORTS=9000-9019` หน้า `bash` |
| ถอนการติดตั้ง | `cd /opt/webmix-gateway/server/deploy && sudo docker compose down -v && sudo rm -rf /opt/webmix-gateway` |

### รันเองแบบไม่ใช้ Docker

```bash
# ต้องมี Node.js 18+ และ ffmpeg ติดตั้งในเครื่องที่รัน Gateway
cd server
npm install
STREAM_TOKEN=รหัสลับของคุณ PORT=8080 npm start
```

ในหน้า WebMix กดปุ่มตั้งค่า (ไอคอนแถบเลื่อน) → แท็บ **การสตรีม**:

- Stream Gateway ใส่ `wss://โดเมนของคุณ:8080/?token=รหัสลับของคุณ`
- กด **เพิ่มปลายทาง** ตามจำนวนช่องที่ต้องการ เลือกแพลตฟอร์ม (YouTube / Facebook / Twitch / RTMP อื่น ๆ)
  แล้วใส่ Stream Key ของแต่ละช่อง (ช่องที่ติ๊กไว้คือช่องที่จะเริ่มเมื่อกด “เริ่มทั้งหมด”)
- กด **STREAM** ที่แถบด้านบน (หรือแถบสถานะ STREAM ด้านล่าง) เพื่อเปิดแผงปลายทาง:
  - กด **เริ่ม** ที่ช่องใดก็ได้ เพื่อไลฟ์เฉพาะช่องนั้น แล้วค่อยเริ่มช่องอื่นเพิ่มทีหลังได้
  - กด **เริ่มทั้งหมด** เพื่อเริ่มทุกช่องที่ติ๊กไว้พร้อมกัน
  - กด **หยุด** ทีละช่อง หรือ **หยุดทั้งหมด** — เมื่อหยุดช่องสุดท้าย ระบบจะตัดการเชื่อมต่อ Gateway ให้เอง
- ความละเอียด เฟรมเรต และบิตเรตตั้งได้ในแท็บ **เอาต์พุต**

หมายเหตุ

- หน้าเว็บที่เปิดผ่าน HTTPS (เช่น GitHub Pages) ต้องใช้ `wss://` ดังนั้นควรวาง Gateway ไว้หลัง reverse proxy ที่มี TLS
  (เช่น Caddy / Nginx) — ถ้าทดสอบในเครื่องตัวเองผ่าน `http://localhost` ใช้ `ws://localhost:8080` ได้
- ควรตั้ง `STREAM_TOKEN` ทุกครั้งที่เปิด Gateway ให้เข้าถึงจากอินเทอร์เน็ต ไม่เช่นนั้นใครก็ใช้เครื่องคุณส่งสตรีมได้

## ใช้ Gateway ร่วมกันหลายคน และการเฝ้าระวัง

**Token แยกรายคน** — ให้แต่ละคน/แต่ละทีมมี token ของตัวเอง ยกเลิกหรือออกใหม่ได้ทันทีโดยไม่กระทบคนอื่น

```bash
cd /opt/webmix-gateway/server/deploy
docker compose exec gateway node stream-gateway.js user add somchai                 # แสดง token ครั้งเดียว
docker compose exec gateway node stream-gateway.js user add newsroom --streams 2 --destinations 4 --srt 3
docker compose exec gateway node stream-gateway.js user list
docker compose exec gateway node stream-gateway.js user token somchai               # ออก token ใหม่ (อันเก่าใช้ไม่ได้ทันที)
docker compose exec gateway node stream-gateway.js user disable somchai             # ระงับ (enable เพื่อเปิดคืน, remove เพื่อลบ)
```

- ผู้ใช้ใส่ `wss://โดเมน/?token=<token ของตัวเอง>` ในหน้าตั้งค่าของ WebMix
- โควตาเริ่มต้นต่อคน: สตรีมพร้อมกัน 1, ปลายทาง 6, SRT ขาเข้า 2 — เกินแล้ว WebMix แสดงเหตุผลเป็นภาษาไทย
- เซิร์ฟเวอร์ทั้งเครื่องสตรีมพร้อมกันได้ `MAX_STREAMS` สตรีม (install.sh ตั้งให้ = จำนวนคอร์ ÷ 2) กันเครื่องรับไม่ไหวจนทุกคนกระตุก
- ไฟล์ผู้ใช้เก็บเฉพาะค่า hash ของ token และอยู่ใน volume จึงไม่หายเมื่ออัปเดต
- `STREAM_TOKEN` เดิมคือผู้ดูแลระบบ (ไม่จำกัดโควตาต่อคน)
- ใส่ token ผิดเกิน 10 ครั้งใน 5 นาที IP นั้นจะถูกบล็อก 15 นาที
- การเชื่อมต่อที่ค้าง (เน็ตหลุดแบบไม่ปิด) ถูกตัดภายใน ~30 วินาที และถ้าคนเดิมเชื่อมต่อกลับมา ระบบแทนที่ของเก่าให้ทันที ไม่ติดโควตา

**หน้าผู้ดูแล** — เปิด `https://โดเมน/admin` แล้วใส่ `STREAM_TOKEN` (เก็บไว้ในแท็บนั้นเท่านั้น ปิดแท็บแล้วต้องใส่ใหม่)
- **หน้าแรก**: สรุปเป็นคำเดียวว่าปกติหรือมีปัญหา · ไลฟ์ได้อีกกี่รายการ (`MAX_STREAMS`) · เครื่องหนักแค่ไหน · เน็ตขาออก (ตั้ง `UPLINK_MBPS=` ตอนรัน install.sh)
  · ไลฟ์ของทุกคนพร้อมสถานะแต่ละปลายทาง และปุ่ม **หยุดไลฟ์นี้** (แอปของเจ้าตัวแจ้งว่าผู้ดูแลหยุด และไม่ต่อใหม่เอง)
  · เหตุการณ์ล่าสุด · ปุ่ม **พักรับไลฟ์ใหม่** ก่อนปิด/ย้ายเครื่องเอง (install.sh ทำให้เองตอนอัปเดต)
- **คนที่ใช้งาน**: เพิ่มคนแล้วได้ **ลิงก์เชิญ** — เจ้าตัวเปิดลิงก์แล้ว WebMix ตั้ง Gateway ให้เอง (รหัสอยู่หลัง `#` ไม่ถูกส่งไปเว็บเซิร์ฟเวอร์)
  · เลือกแพ็กเกจ ไลฟ์ทั่วไป / ร้านค้า-เพจ / สถานี-งานใหญ่ หรือกำหนดตัวเลขเอง · พักการใช้งาน (ย้อนกลับได้) · ทำรหัสใหม่ · ลบ
  · ติ๊ก "ให้เป็นผู้ดูแลด้วย" เพื่อให้คนนั้นเปิดหน้านี้ได้ด้วยรหัสของตัวเอง
- ไม่แสดง Stream Key ของใคร · คำสั่งแก้ไขต้องส่ง token ทาง `Authorization` เท่านั้น · ลิงก์เดิม `/admin?token=…` ยังใช้ได้ (รหัสถูกลบออกจากแถบที่อยู่ทันที)

**แจ้งเตือนเข้ามือถือ** — รัน install.sh ซ้ำพร้อมช่องทางที่ต้องการ:

```bash
curl -fsSL https://raw.githubusercontent.com/jugkritso-png/webswither/HEAD/server/deploy/install.sh | \
  sudo ALERT_WEBHOOK=https://discord.com/api/webhooks/... bash
# หรือ Telegram
curl -fsSL https://raw.githubusercontent.com/jugkritso-png/webswither/HEAD/server/deploy/install.sh | \
  sudo TELEGRAM_BOT_TOKEN=123:ABC TELEGRAM_CHAT_ID=-100123 bash
```

แจ้งเมื่อ: ปลายทางหลุดนานเกิน 20 วินาที (และแจ้งอีกครั้งเมื่อกลับมา), สตรีมที่กำลังไลฟ์หลุดจาก WebMix และไม่กลับมาใน 30 วินาที,
เข้ารหัสไม่ทันเวลาจริง (ภาพจะกระตุก), สัญญาณ SRT ขาเข้าหาย, CPU/หน่วยความจำของเซิร์ฟเวอร์เต็ม, เซิร์ฟเวอร์เต็มจนมีคนเริ่มสตรีมไม่ได้
และมีคนพยายามเดา token — ใช้ได้กับ Discord, Slack, Google Chat (webhook) และ Telegram

**Prometheus / Grafana** — `GET /metrics` (ส่ง `Authorization: Bearer <STREAM_TOKEN>` หรือตั้ง `METRICS_TOKEN` แยก)

## ส่งสัญญาณด้วย SRT

SRT (Secure Reliable Transport) ทนอินเทอร์เน็ตกระตุก/แพ็กเก็ตหายได้ดีกว่า RTMP และเข้ารหัส AES ได้
เหมาะสำหรับส่งเข้า **vMix, OBS, Wowza, Haivision, SRT Live Server, MediaMTX** หรือห้องควบคุม/สถานีปลายทาง

1. ตั้งค่า → แท็บ **การสตรีม** → **เพิ่มปลายทาง** → เลือกแพลตฟอร์ม **SRT**
2. ใส่ `srt://host:port` ของฝั่งรับ (ฝั่งรับต้องเปิดโหมด **listener**)
3. ใส่ **Stream ID** (ถ้าฝั่งรับต้องการ เช่น SRT Live Server / MediaMTX ใช้ระบุชื่อสตรีม)
4. ใส่ **รหัสผ่านเข้ารหัส** 10–64 ตัวอักษร (ถ้าฝั่งรับตั้งไว้ — ต้องตรงกันทั้งสองฝั่ง)
5. เลือก **Latency**: ในเครือข่ายเดียวกัน 120–200 ms · ผ่านอินเทอร์เน็ต 500–2000 ms (ยิ่งสูงยิ่งทนเน็ตกระตุก แต่ดีเลย์มากขึ้น)

ส่ง SRT ร่วมกับ RTMP (เช่น YouTube) ได้ในการไลฟ์ครั้งเดียวกัน — Gateway ส่ง SRT เป็น MPEG-TS แบบ caller
จึงไม่ต้องเปิดพอร์ตเพิ่มบนเซิร์ฟเวอร์ Gateway (เปิดพอร์ต UDP ที่ฝั่งรับแทน)

## รับสัญญาณ SRT เข้ามาเป็น Input (จาก OBS / vMix / encoder / กล้อง)

เบราว์เซอร์รับ SRT เองไม่ได้ Stream Gateway จึงรับแทนแล้วส่งต่อให้ WebMix ผ่าน WebSocket
(วิดีโอ H.264 ส่งต่อโดยไม่เข้ารหัสใหม่ จึงแทบไม่ใช้ CPU แม้เป็น 4K · ถ้าเป็น H.265/HEVC จะแปลงเป็น H.264 ให้อัตโนมัติ)

1. ตั้งค่า Stream Gateway ให้เรียบร้อยก่อน (ดูหัวข้อด้านบน)
2. กด **เพิ่ม Input → สัญญาณ SRT** แล้วเลือกวิธีรับ:
   - **รอรับ (ผู้ส่งเชื่อมต่อเข้ามา)** — เลือกพอร์ต (9000–9009) ระบบจะแสดงค่าที่ต้องใส่ในโปรแกรมผู้ส่ง เช่น OBS:
     `srt://โดเมน-gateway:9000?mode=caller&latency=500000`
   - **ดึงจาก SRT Server** — ใส่ `srt://host:port` ของต้นทาง (ต้นทางเป็นโหมด listener) และ Stream ID ถ้ามี
3. ใส่รหัสผ่านเข้ารหัสและ Latency ให้ตรงกับฝั่งผู้ส่ง แล้วเริ่มส่งภาพ — ภาพและเสียงจะขึ้นใน Input นั้นอัตโนมัติ

- ต้องเปิดพอร์ต **UDP 9000–9009** ในไฟร์วอลล์ของผู้ให้บริการเซิร์ฟเวอร์ (สคริปต์ติดตั้งเปิดใน ufw และ Docker ให้แล้ว)
  เปลี่ยนช่วงพอร์ตได้ด้วย `SRT_PORTS=9000-9019` ตอนรันคำสั่งติดตั้ง
- ถ้าผู้ส่งหยุดหรือหลุด Input จะขึ้น WAITING / NO SIGNAL และรับสัญญาณใหม่เองเมื่อผู้ส่งกลับมา
- Input SRT ถูกจำไว้และเชื่อมต่อใหม่ให้อัตโนมัติเมื่อเปิดหน้าเว็บครั้งถัดไป
- ใช้ได้บน Chrome, Edge, Firefox, Safari (คอมพิวเตอร์และ iPad) — iPhone ต้องเป็น iOS 17.1 ขึ้นไป
- ถ้าส่งจาก OBS และตั้งรหัสผ่าน ควรใช้รหัสที่ไม่มีอักขระ `& # ?` หรือช่องว่าง (OBS อ่านรหัสจาก URL)

## NDI® และ OMT ในวง LAN (แอปเดสก์ท็อป)

รับ/ส่งภาพคุณภาพสูงกับ vMix, OBS (ปลั๊กอิน DistroAV), NDI Studio Monitor และกล้อง PTZ ที่อยู่ในวง LAN เดียวกัน — ใช้ได้กับ Gateway ในแอปเดสก์ท็อป (Gateway บนเซิร์ฟเวอร์ใช้ไม่ได้)

- **ส่ง Program ออก**: ตั้งค่า → การสตรีม → เพิ่มปลายทาง “NDI®” หรือ “OMT” แล้วตั้งชื่อแหล่ง (เช่น `WebMix Program`) → กดเริ่มในแผง STREAM · แผงแสดงจำนวนเครื่องที่กำลังรับ
- **รับเข้ามาเป็นแหล่งภาพ**: เพิ่มแหล่งภาพ → “NDI® / OMT” → เลือกจากรายการที่ค้นเจอในวง LAN (หรือพิมพ์ชื่อเอง) · แหล่งหายไปแล้วกลับมา จะต่อให้เอง
- **NDI** ต้องติดตั้ง **NDI Tools** (ฟรี) จาก https://ndi.video/tools ในเครื่องที่รัน WebMix ก่อน — ไลบรารีของ NDI แจกต่อไม่ได้ แอปจึงใช้ NDI Runtime ที่ติดตั้งไว้ (Linux: วาง `libndi.so.6` ไว้ในพาธของระบบ)
- **OMT** (Open Media Transport ของ vMix, โอเพนซอร์ส MIT) มีไลบรารีมากับแอปบน Windows / macOS · Linux: วาง `libomt.so` และ `libvmx.so` ไว้ข้างโปรแกรม
- ภาพช้ากว่าต้นทางราว 0.2–0.5 วินาที (แปลงผ่าน H.264 เพื่อให้เบราว์เซอร์แสดงได้) · ค้นหาไม่เจอเพราะอยู่คนละวง: ตั้งตัวแปร `WEBMIX_NDI_EXTRA_IPS=192.168.1.20,…` ก่อนเปิดแอป
- ทดสอบไลบรารีในเครื่อง: `webmix-gateway --netvideo-selftest ndi` (หรือ `omt`) — สร้างแหล่ง ค้นหา แล้วรับภาพและเสียงกลับมาเอง

NDI® เป็นเครื่องหมายการค้าจดทะเบียนของ Vizrt NDI AB
