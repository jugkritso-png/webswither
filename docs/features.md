# ฟีเจอร์ของสตูดิโอ

รายละเอียดฟีเจอร์หลักของสตูดิโอ — กลับไปที่ [README](../README.md)

## Overlay แบบ vMix

- **Overlay 1–8** ซ้อนแหล่งภาพใดก็ได้ (กล้อง, วิดีโอ, รูป PNG โปร่งใส, Title, SRT, มือถือ) บน Program พร้อมกันสูงสุด 8 ชั้น โดยไม่กระทบการตัดภาพหลัก — 8 อยู่บนสุด
- กดปุ่ม **1–8 ใต้การ์ด Input** เพื่อซ้อนทันที (กดซ้ำเพื่อเอาออก) · ปุ่ม OVERLAY ในแผง TRANSITION หรือคีย์ **Q W E R** (1–4) และ **Shift + Q W E R** (5–8)
- แท็บ **OVERLAY**: เลือก Input, เอฟเฟกต์เข้า-ออก (Cut / Fade / Zoom / Slide ← → ↑ ↓ / Wipe), ระยะเวลา และ **PVW** ดูบน Preview ก่อนขึ้นจอ
- ปุ่ม **⧉ บนการ์ด** = ตำแหน่งของ Input: X/Y, ขนาด, ครอป 4 ด้าน, ความทึบ, ขอบ และ **คีย์ฉากเขียว/ฟ้าแยกราย Input** (ใช้ GPU) พร้อม preset มุมจอ/ครึ่งจอ
- Input ใหม่ **Title กราฟิกข้อความ** พื้นโปร่งใส 4 แบบ: ป้ายชื่อล่าง, แถบหัวข้อบน, ป้าย LIVE, ข้อความกลางจอ — แก้ข้อความแล้วบนจอเปลี่ยนทันที
- Tally / AFV นับ Overlay ว่าออกอากาศ · การผูก Input, เอฟเฟกต์ และตำแหน่งบันทึกในโชว์ (เปิดหน้าใหม่แล้วไม่มีอะไรขึ้นจอเอง)

## CG Studio (ส่วนเสริมออกแบบกราฟิก)

เปิดจาก **เพิ่มแหล่งภาพ → CG Studio** — WebMix เพิ่ม Input กราฟิกและเปิดหน้าออกแบบแยกต่างหาก (`cg-studio.html`) ให้โดยอัตโนมัติ หน้านี้เชื่อมกับ Input ผ่าน protocol แบบ versioned บน `BroadcastChannel` บน origin เดียวกัน จึงส่งการแก้ไขไป WebMix ได้ทันทีโดยไม่ต้องตั้งเซิร์ฟเวอร์เพิ่ม

- ออกแบบแบบหลาย Scene ด้วย Elements Tree, เพิ่ม Text / Shape / Image / Ticker, ลากวางและปรับขนาดบน Canvas, จัดลำดับ/ซ่อน/ล็อก/ทำซ้ำ Layers และ Undo/Redo
- Inspector ปรับตำแหน่ง, ขนาด, ฟอนต์, สี, ความโค้ง และความเร็วตัววิ่ง; มี safe-area guides และ template เริ่มต้น 6 แบบที่แก้ต่อได้
- ตั้ง Transition IN/OUT แล้วส่งไป Preview, Take หรือ Clear ผ่าน Overlay 1–8; การเปลี่ยน Scene ใน Editor ไม่สลับ Scene บน Program จนกด Take
- เอกสาร CG schema v2 และ Input อยู่ใน WebMix Show; เปิด Show เก่าได้ด้วย migration จาก template schema v1
- บันทึก preset ในเครื่องและส่งออก/นำเข้าไฟล์ `.webmix-cg.json`; รูปในเอกสารฝังไปกับ CG (PNG/JPEG/WebP ไม่เกิน 1 MB ต่อรูป และ 1.5 MB รวมหลังเข้ารหัสต่อ CG) เพื่อให้ไฟล์ CG ย้ายเครื่องได้
- จำกัดขนาด Show ที่เก็บใน browser ตาม quota ของ localStorage; ถ้าเกินระบบปฏิเสธการแก้ CG ล่าสุดและแสดงข้อความให้ลดขนาด/จำนวนภาพ
- หากเปิดหน้า CG Studio โดยตรง จะใช้โหมดออกแบบและนำเข้า/ส่งออกไฟล์ได้; การซิงก์สดต้องเปิดจาก Input CG Studio ใน WebMix และอยู่บน origin เดียวกัน

## ระบบวาดภาพด้วยการ์ดจอ (GPU)

Program/Preview วาดด้วย WebGL บนการ์ดจอ: วิดีโอส่งเป็น texture ตรง ๆ ส่วนคีย์ฉากเขียว ครอป และความทึบ
ทำใน shader ขั้นตอนเดียว จึงลื่นกว่าแบบ CPU มากเมื่อใช้ 4K และซ้อน Overlay หลายชั้น

- ตั้งที่ **ตั้งค่า → เอาต์พุต → ระบบวาดภาพ**: อัตโนมัติ (แนะนำ) / GPU / CPU — หน้าตั้งค่าแสดงชื่อการ์ดจอที่พบ
- โหมดอัตโนมัติใช้ GPU เมื่อมีการ์ดจอจริง ถ้าเป็นการ์ดจอจำลองด้วยซอฟต์แวร์ (เช่น เครื่องเสมือน) จะใช้ CPU
- ถ้าการ์ดจอล่มระหว่างไลฟ์ (ไดรเวอร์รีเซ็ต) ระบบสลับไป CPU ทันทีโดยภาพไม่ดับ
- แถบสถานะด้านล่างแสดง `ENGINE GPU/CPU · fps · ms` ต่อเฟรม

## แขกรับเชิญทางไกล (แบบ vMix Call)

- **เพิ่ม Input → แขกรับเชิญทางไกล** → ตั้งชื่อ → ได้ลิงก์เชิญ + QR Code ส่งให้แขกทาง LINE/อีเมล
- แขกเปิดลิงก์บนมือถือหรือคอมพิวเตอร์ (ไม่ต้องติดตั้งแอป) กด **เข้าร่วม** → กล้อง+ไมค์เข้ามาเป็น Input ในสตูดิโอ
- แขก **เห็นและได้ยินรายการ** จากสตูดิโอ (ภาพ ~720p) โดย **ไม่ได้ยินเสียงตัวเองย้อนกลับ** (mix-minus — เสียงทุกช่องยกเว้นของแขกคนนั้น)
- แขกเห็นกรอบ **ON AIR** เมื่อภาพของตัวเองออกอากาศ (รวมเมื่ออยู่บน Overlay) และ PREVIEW เมื่อเตรียมขึ้นจอ · ปิดไมค์/ปิดกล้อง/สลับกล้องเองได้
- ลิงก์ของแต่ละแขกใช้ได้คนเดียว (เปิดซ้ำจะถูกปฏิเสธ) · ปุ่ม 🔗 บนการ์ดแขกเปิดลิงก์เชิญอีกครั้ง · ลบการ์ด = จบการเชื่อมต่อของแขกคนนั้น
- รีเฟรชสตูดิโอหรือเน็ตแขกหลุด แขกจะเชื่อมต่อกลับเข้าช่องเดิมเอง (แขกที่เชิญไว้บันทึกอยู่ในโชว์)
- ตั้ง Stream Gateway ไว้ แขกที่ใช้ 4G/5G หรือ Wi-Fi บริษัทจะเชื่อมต่อผ่าน TURN ได้ · แนะนำให้แขกใส่หูฟัง

## Multiview (จอที่สอง)

ปุ่ม **ตาราง** ด้านบน (หรือคีย์ **M**) เปิดหน้าต่าง Multiview 1920×1080 สำหรับลากไปจอที่สองแล้วดับเบิลคลิกเต็มจอ:
Preview (กรอบเขียว) และ Program (กรอบแดง) ด้านบน, ทุก Input ด้านล่างพร้อมเลข ชื่อ tally (PGM / PVW / OV1–8) และมิเตอร์เสียง,
แถบบนแสดงเวลา สถานะ STREAM/REC และความละเอียด — รองรับได้ถึง 24 Input · วาดเฉพาะตอนเปิดหน้าต่างไว้ (15 fps) จึงไม่กินเครื่อง

## Playlist

**เพิ่ม Input → Playlist** แล้วเลือกวิดีโอ/รูปหลายไฟล์ — เล่นต่อกันอัตโนมัติ (วิดีโอจบแล้วไปรายการถัดไป, รูปแสดงตามเวลาที่ตั้ง)
ปุ่ม **‹ ⏯ › 🔁** บนการ์ดควบคุมระหว่างไลฟ์ · ปุ่มดินสอเปิดหน้าแก้ไข: เพิ่มไฟล์, เลื่อนลำดับ, ลบ, เล่นรายการที่เลือก, เวลาแสดงรูป, วนซ้ำ
ไฟล์เก็บไว้ในเบราว์เซอร์ เปิดหน้าใหม่แล้ว Playlist อยู่ครบ · เสียงทั้งรายการอยู่ในช่องมิกเซอร์ช่องเดียว · ใช้เป็น Overlay ได้เหมือน Input อื่น

## กราฟิกข้อมูล และข้อมูลจาก Google Sheets

เพิ่มจาก **เพิ่ม Input** — ทุกแบบมีพื้นโปร่งใส กดปุ่ม 1–8 ใต้การ์ดเพื่อซ้อนบน Program ได้ทันที

- **นาฬิกานับถอยหลัง / จับเวลา** — นับถอยหลังตามระยะเวลา, จับเวลานับขึ้น หรือนับถึงเวลาที่กำหนด (เช่น 19:00)
  3 รูปแบบ (ใหญ่กลางจอ / กล่องมุมขวาบน / แถบล่าง) · ปุ่ม ▶/⏸ ⟲ บนการ์ด · หมดเวลาแล้วตัวเลขกะพริบแดง
- **ป้ายคะแนน** — ชื่อทีม สีทีม คะแนน ช่วงเวลา และนาฬิกาการแข่งขัน · ปุ่ม **A+ A− B+ B−** บนการ์ดเปลี่ยนคะแนนทันทีระหว่างไลฟ์
- **ตัววิ่งข่าว (Ticker)** — ป้ายหัว + ข้อความวิ่งต่อเนื่อง ปรับความเร็วได้
- **ข้อมูลจาก Google Sheets / CSV** (ช่องในหน้าแก้ไขของ Title, ป้ายคะแนน, ตัววิ่ง) — วางลิงก์ชีตปกติได้เลย
  (ชีตต้องแชร์แบบ “ทุกคนที่มีลิงก์ดูได้”) ระบบดึงข้อมูลใหม่ทุก 10 วินาที แก้ในชีตแล้วบนจอเปลี่ยนเอง
  - Title: คอลัมน์ A = ข้อความหลัก, B = ข้อความรอง — แต่ละแถวคือป้ายหนึ่งชุด กด **‹ ›** บนการ์ดเพื่อไล่รายชื่อ (rundown)
  - ตัววิ่ง: คอลัมน์ A ของทุกแถว · ป้ายคะแนน: แถวแรก A–E = ทีม A, คะแนน A, ทีม B, คะแนน B, ช่วงเวลา
  - ดึงข้อมูลไม่ได้ การ์ดขึ้น **DATA ERROR** และแจ้งเตือน (ข้อมูลล่าสุดยังแสดงอยู่)

## บันทึกวิดีโอ

ปุ่ม **● REC** เลือกฟอร์แมตที่เบราว์เซอร์รองรับให้อัตโนมัติ (Chrome/Firefox ได้ `.webm`, Safari ได้ `.mp4`)
ที่ 1440p/4K ระบบจะเลือก H.264 (`.mp4`) ก่อนถ้าเบราว์เซอร์รองรับ เพราะใช้ชิปเข้ารหัสในเครื่องได้และเบากว่า VP9 มาก

ไฟล์ถูกเขียนลงดิสก์ระหว่างบันทึก (ไม่เก็บใน RAM) จึงบันทึกนานหลายชั่วโมงได้:
- Chrome / Edge: เลือก **โฟลเดอร์บันทึกวิดีโอ** ที่ ตั้งค่า → เอาต์พุต แล้วไฟล์จะถูกเขียนลงโฟลเดอร์นั้นโดยตรง
- ถ้าไม่ได้เลือกโฟลเดอร์ ไฟล์จะถูกเขียนลงพื้นที่ชั่วคราวของเบราว์เซอร์บนดิสก์ แล้วดาวน์โหลดเมื่อกดหยุด

ไฟล์ WebM จาก MediaRecorder ปกติไม่มีความยาวและไม่มีดัชนี จึงลากแถบเวลาไม่ได้ — WebMix เพิ่ม Duration, Cues และ SeekHead
ให้ระหว่างเขียนไฟล์ (ไม่ต้องโหลดทั้งไฟล์เข้า RAM) ไฟล์ที่ได้จึงแสดงความยาวและเลื่อนหาตำแหน่งได้ทั้งในเบราว์เซอร์, VLC และโปรแกรมตัดต่อ

## บันทึกโชว์

โชว์ = Input ทั้งหมด (ลำดับ ชื่อ ข้อความ), Program/Preview, มิกเซอร์เสียง (ระดับ, Mute, AFV, EQ/คอมเพรสเซอร์/ดีเลย์), กราฟิก และ preset ป้ายชื่อ

- **บันทึกอัตโนมัติ** ในเบราว์เซอร์ทุกครั้งที่มีการเปลี่ยนแปลง — รีเฟรช, เบราว์เซอร์ปิดไปเอง หรือเปิดเครื่องใหม่ โชว์กลับมาครบ
- ไฟล์วิดีโอ/รูปเก็บสำเนาไว้ในพื้นที่ของเบราว์เซอร์ จึงไม่ต้องเลือกไฟล์ใหม่ · กล้องและไมค์เปิดอุปกรณ์เดิมให้เอง (ถ้ารหัสอุปกรณ์เปลี่ยนจะหาจากชื่อ)
- กล้องมือถือที่เคยเชื่อมต่อจะกลับเข้าช่องเดิมเอง · แชร์หน้าจอ/ไฟล์ที่หาไม่พบจะแสดงปุ่ม 🔗 บนการ์ดเพื่อเชื่อมต่อใหม่
- กราฟิกจะไม่ขึ้นจอเองหลังรีเฟรช (ป้องกันภาพหลุดออกอากาศ)
- ปุ่ม **โฟลเดอร์** ด้านบน: ตั้งชื่อโชว์, **บันทึกเป็นไฟล์** `.webmix.json`, **เปิดไฟล์โชว์** และ **เริ่มโชว์ใหม่**
  ไฟล์โชว์ไม่รวมตัวไฟล์วิดีโอ/รูป (เปิดบนเครื่องอื่นแล้วกด 🔗 เพื่อเลือกไฟล์) และมี Stream Key/รหัส SRT เฉพาะเมื่อเลือก “จำ Stream Key” ไว้
- **Preset ป้ายชื่อ** ในแท็บ TITLE: กด “+ บันทึกป้ายนี้” แล้วแตะเพื่อสลับชื่อ/ตำแหน่ง/สีระหว่างรายการ

## ความทนทานระหว่างไลฟ์

- ถ้าการเชื่อมต่อกับ Stream Gateway หลุด (เน็ตสะดุด, Gateway รีสตาร์ท หรือค้าง) ปุ่มจะขึ้น **RECONNECTING**
  และระบบจะเชื่อมต่อใหม่ (1 → 2 → 4 → 8 → 10 วินาที) แล้วเริ่มปลายทางที่ไลฟ์อยู่ให้เอง โดยไฟ ON AIR และเวลาออกอากาศยังเดินต่อ
- ปลายทางที่หลุดเฉพาะช่องจะลองใหม่ทุก 5 วินาที, ไม่มีสัญญาณจาก Gateway เกิน 8 วินาทีถือว่าค้างและเชื่อมต่อใหม่

## การใช้งาน 4K

- ตั้งค่า → แท็บ **เอาต์พุต** → เลือก **3840 × 2160 (4K UHD)** ระบบจะใส่บิตเรตแนะนำให้ (4K30 ≈ 25000 kbps, 4K60 ≈ 37500 kbps)
- เพิ่มกล้องแล้วเลือกความละเอียด **4K UHD** — ถ้ากล้องรองรับไม่ถึง ระบบจะแจ้งความละเอียดที่ได้จริง และการ์ดของแต่ละ Input แสดงความละเอียดจริงเสมอ
- กล้องมือถือ: แตะปุ่ม **HD / FHD / 4K** บนหน้าจอมือถือเพื่อเลือกคุณภาพที่ส่งเข้าสตูดิโอ
- คอมพิวเตอร์ที่เปิด WebMix ควรมี CPU 8 คอร์ขึ้นไปหรือการ์ดจอแยก และอินเทอร์เน็ตขาขึ้นอย่างน้อย 1.5 เท่าของบิตเรต (4K30 ≈ 40 Mbps)
- YouTube รับได้ถึง 4K · Facebook และ Twitch รับสูงสุด 1080p (ระบบจะเตือนเมื่อเริ่มสตรีม 4K ไปปลายทางเหล่านี้)
