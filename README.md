# WebMix Broadcast Pro

ระบบสลับภาพและเสียง (live production switcher) ที่ทำงานบนเว็บเบราว์เซอร์ ใช้ได้ทั้งคอมพิวเตอร์ แท็บเล็ต และมือถือ
รองรับความละเอียดสูงสุด **4K (3840 × 2160)** ทั้งระบบ — กล้อง, Program, กราฟิก, การบันทึก, การสตรีม และกล้องมือถือ

- จอ Preview / Program, ปุ่ม CUT / AUTO / FTB และ T-Bar (เอฟเฟกต์ MIX, DIP, WIPE เลือกเวลาได้)
- Input: กล้อง/แคปเจอร์การ์ด (เลือกอุปกรณ์และความละเอียด), แชร์หน้าจอ, ไฟล์วิดีโอ (เล่น/หยุด/วนซ้ำ), ภาพนิ่ง,
  Color Bars, Slate ข้อความ, นาฬิกา, Black และกล้องมือถือไร้สายผ่าน QR Code (มีไฟ Tally บนมือถือ)
- กราฟิก: ป้ายชื่อ Lower Third พร้อมแอนิเมชัน, ภาพซ้อน PIP, Chroma Key ฉากเขียว/ฟ้า
- มิกเซอร์เสียง: มิเตอร์ dBFS จริง, เฟดเดอร์, Mute, Audio Follow Video, ฟังเสียงผ่านหูฟัง (MON),
  ลิมิตเตอร์ที่ Master และ FX ต่อช่อง (หน่วงเสียง, EQ 3 ย่าน, คอมเพรสเซอร์)
- บันทึกวิดีโอ, **สตรีมสดหลายช่องทางพร้อมกัน** (YouTube / Facebook / Twitch / **SRT** / RTMP อื่น ๆ สูงสุด 6 ปลายทาง),
  ภาพนิ่ง, หน้าต่าง Program Output แยก, เต็มจอ
- คู่มือในแอป (ปุ่ม ?) และดาวน์โหลดคู่มือเป็นไฟล์ Word

โครงสร้างไฟล์: `index.html` (หน้าเว็บ), `assets/app.css` (ดีไซน์), `assets/app.js` (การทำงาน), `server/` (Stream Gateway)

## เปิดใช้งานผ่าน GitHub Pages (HTTPS)

กล้องมือถือไร้สายต้องเปิดผ่าน **HTTPS** เท่านั้น (ถ้าเปิดไฟล์จากเครื่องตรง ๆ มือถือจะเปิดลิงก์ใน QR ไม่ได้)

1. ไปที่ **Settings → Pages** ของ repo นี้
2. ที่ **Build and deployment → Source** เลือก **GitHub Actions**
3. push ขึ้น branch หลัก (default branch) — workflow `.github/workflows/pages.yml` จะ deploy ให้อัตโนมัติ
   หรือกด **Actions → Deploy to GitHub Pages → Run workflow**
4. เปิดใช้งานที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

ลิงก์/QR ของกล้องมือถือจะคงเดิมแม้รีเฟรชหน้า และมือถือจะเชื่อมต่อกลับเข้ามาเองเมื่อสตูดิโอออนไลน์อีกครั้ง

เมื่อตั้งค่า Stream Gateway แล้ว กล้องมือถือจะเชื่อมต่อผ่าน **PeerJS และ TURN server ของ Gateway เอง** (แถบสถานะขึ้น `WIRELESS READY · TURN`)
มือถือที่ใช้ 4G/5G หรือ Wi-Fi ที่ปิดกั้น WebRTC จึงส่งภาพได้ — ลิงก์/QR มีรหัส TURN ชั่วคราว (7 วัน) แต่ไม่มี token ของ Gateway
ถ้ายังไม่ได้ตั้ง Gateway จะใช้เซิร์ฟเวอร์ PeerJS สาธารณะแทน ซึ่งมือถือบางเครือข่ายอาจเชื่อมต่อไม่ได้

## Overlay แบบ vMix

- **Overlay 1–8** ซ้อนแหล่งภาพใดก็ได้ (กล้อง, วิดีโอ, รูป PNG โปร่งใส, Title, SRT, มือถือ) บน Program พร้อมกันสูงสุด 8 ชั้น โดยไม่กระทบการตัดภาพหลัก — 8 อยู่บนสุด
- กดปุ่ม **1–8 ใต้การ์ด Input** เพื่อซ้อนทันที (กดซ้ำเพื่อเอาออก) · ปุ่ม OVERLAY ในแผง TRANSITION หรือคีย์ **Q W E R** (1–4) และ **Shift + Q W E R** (5–8)
- แท็บ **OVERLAY**: เลือก Input, เอฟเฟกต์เข้า-ออก (Cut / Fade / Zoom / Slide ← → ↑ ↓ / Wipe), ระยะเวลา และ **PVW** ดูบน Preview ก่อนขึ้นจอ
- ปุ่ม **⧉ บนการ์ด** = ตำแหน่งของ Input: X/Y, ขนาด, ครอป 4 ด้าน, ความทึบ, ขอบ และ **คีย์ฉากเขียว/ฟ้าแยกราย Input** (ใช้ GPU) พร้อม preset มุมจอ/ครึ่งจอ
- Input ใหม่ **Title กราฟิกข้อความ** พื้นโปร่งใส 4 แบบ: ป้ายชื่อล่าง, แถบหัวข้อบน, ป้าย LIVE, ข้อความกลางจอ — แก้ข้อความแล้วบนจอเปลี่ยนทันที
- Tally / AFV นับ Overlay ว่าออกอากาศ · การผูก Input, เอฟเฟกต์ และตำแหน่งบันทึกในโชว์ (เปิดหน้าใหม่แล้วไม่มีอะไรขึ้นจอเอง)

## ระบบวาดภาพด้วยการ์ดจอ (GPU)

Program/Preview วาดด้วย WebGL บนการ์ดจอ: วิดีโอส่งเป็น texture ตรง ๆ ส่วนคีย์ฉากเขียว ครอป และความทึบ
ทำใน shader ขั้นตอนเดียว จึงลื่นกว่าแบบ CPU มากเมื่อใช้ 4K และซ้อน Overlay หลายชั้น

- ตั้งที่ **ตั้งค่า → เอาต์พุต → ระบบวาดภาพ**: อัตโนมัติ (แนะนำ) / GPU / CPU — หน้าตั้งค่าแสดงชื่อการ์ดจอที่พบ
- โหมดอัตโนมัติใช้ GPU เมื่อมีการ์ดจอจริง ถ้าเป็นการ์ดจอจำลองด้วยซอฟต์แวร์ (เช่น เครื่องเสมือน) จะใช้ CPU
- ถ้าการ์ดจอล่มระหว่างไลฟ์ (ไดรเวอร์รีเซ็ต) ระบบสลับไป CPU ทันทีโดยภาพไม่ดับ
- แถบสถานะด้านล่างแสดง `ENGINE GPU/CPU · fps · ms` ต่อเฟรม

## แขกรับเชิญทางไกล (แบบ vMix Call)

- **เพิ่ม Input → แขกรับเชิญทางไกล** → ตั้งชื่อ → ได้ลิงก์เชิญ + QR Code ส่งให้แขกทาง LINE/อีเมล
- แขกเปิดลิงก์บนมือถือหรือคอมพิวเตอร์ (ไม่ต้องติดตั้งแอป) กด **เข้าร่วม** → กล้อง+ไมค์เข้ามาเป็น Input ในสตูดิโอ
- แขก **เห็นและได้ยินรายการ** จากสตูดิโอ (ภาพ ~720p) โดย **ไม่ได้ยินเสียงตัวเองย้อนกลับ** (mix-minus — เสียงทุกช่องยกเว้นของแขกคนนั้น)
- แขกเห็นกรอบ **ON AIR** เมื่อภาพของตัวเองออกอากาศ (รวมเมื่ออยู่บน Overlay) และ PREVIEW เมื่อเตรียมขึ้นจอ · ปิดไมค์/ปิดกล้อง/สลับกล้องเองได้
- ลิงก์ของแต่ละแขกใช้ได้คนเดียว (เปิดซ้ำจะถูกปฏิเสธ) · ปุ่ม 🔗 บนการ์ดแขกเปิดลิงก์เชิญอีกครั้ง · ลบการ์ด = จบการเชื่อมต่อของแขกคนนั้น
- รีเฟรชสตูดิโอหรือเน็ตแขกหลุด แขกจะเชื่อมต่อกลับเข้าช่องเดิมเอง (แขกที่เชิญไว้บันทึกอยู่ในโชว์)
- ตั้ง Stream Gateway ไว้ แขกที่ใช้ 4G/5G หรือ Wi-Fi บริษัทจะเชื่อมต่อผ่าน TURN ได้ · แนะนำให้แขกใส่หูฟัง

## Multiview (จอที่สอง)

ปุ่ม **ตาราง** ด้านบน (หรือคีย์ **M**) เปิดหน้าต่าง Multiview 1920×1080 สำหรับลากไปจอที่สองแล้วดับเบิลคลิกเต็มจอ:
Preview (กรอบเขียว) และ Program (กรอบแดง) ด้านบน, ทุก Input ด้านล่างพร้อมเลข ชื่อ tally (PGM / PVW / OV1–8) และมิเตอร์เสียง,
แถบบนแสดงเวลา สถานะ STREAM/REC และความละเอียด — รองรับได้ถึง 24 Input · วาดเฉพาะตอนเปิดหน้าต่างไว้ (15 fps) จึงไม่กินเครื่อง

## สตรีมสด (RTMP) — หลายช่องทางพร้อมกัน

เบราว์เซอร์ส่ง RTMP เองไม่ได้ จึงต้องมี **Stream Gateway** เล็ก ๆ คั่นกลาง:

```
เบราว์เซอร์ ──(WebSocket ครั้งเดียว)──▶ Gateway: FFmpeg เข้ารหัส H.264/AAC ครั้งเดียว
                                          ├──▶ YouTube
                                          ├──▶ Facebook
                                          └──▶ Twitch / RTMP อื่น ๆ
```

- อินเทอร์เน็ตขาขึ้นของเครื่องที่เปิด WebMix ใช้เท่ากับสตรีมช่องเดียว ไม่ว่าจะส่งกี่ปลายทาง
  (Gateway ต้องมีขาขึ้นพอสำหรับทุกปลายทาง เช่น 3 ปลายทาง × 4.5 Mbps ≈ 14 Mbps)
- แต่ละปลายทางเริ่ม/หยุดได้อิสระระหว่างไลฟ์ ปลายทางที่หลุดจะเชื่อมต่อใหม่เองทุก 5 วินาที โดยไม่กระทบช่องอื่น
- จำนวนปลายทางสูงสุดต่อการเชื่อมต่อตั้งได้ด้วยตัวแปร `MAX_DESTINATIONS` (ค่าเริ่มต้น 6)

### ติดตั้ง Gateway บนเซิร์ฟเวอร์ด้วยคำสั่งเดียว (แนะนำ)

ต้องมี VPS ที่ใช้ **Ubuntu 22.04 / 24.04** หรือ **Debian 12** (เช่น DigitalOcean, Vultr, Linode, AWS Lightsail, Google Cloud)

| ใช้งาน | CPU / RAM ขั้นต่ำ |
|---|---|
| 720p30 | 2 vCPU / 2 GB |
| 1080p30 – 1080p60 | 4 vCPU / 4 GB |
| 1440p / 4K30 | 8 vCPU / 8 GB ขึ้นไป (หรือเครื่องที่มีการ์ดจอ NVIDIA) |
| 4K60 | 16 vCPU หรือการ์ดจอ NVIDIA |

ระหว่างไลฟ์ แถบสถานะ STREAM จะแสดงความเร็วการเข้ารหัสของ Gateway (`ENC 1.00x`)
ถ้าต่ำกว่า 1.00x แปลว่าเซิร์ฟเวอร์ไม่แรงพอ ให้ลดความละเอียด/เฟรมเรต หรือใช้เซิร์ฟเวอร์ที่แรงขึ้น

เซิร์ฟเวอร์ที่มีการ์ดจอ NVIDIA (ติดตั้ง NVIDIA Container Toolkit แล้ว) ใช้การ์ดจอเข้ารหัสได้ด้วย `VIDEO_ENCODER=h264_nvenc`
(ถ้ารันแบบ Docker ต้องเพิ่ม `gpus: all` ให้ service `gateway` ใน `docker-compose.yml` ด้วย)

1. เปิดพอร์ตในไฟร์วอลล์ของผู้ให้บริการ (Security Group / Firewall rules):
   - TCP **80, 443** — หน้าเว็บ/HTTPS/WebSocket
   - TCP+UDP **3478** และ UDP **49160–49250** — TURN สำหรับกล้องมือถือ
   - UDP **9000–9009** — รับสัญญาณ SRT
2. SSH เข้าเซิร์ฟเวอร์แล้วรัน:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/jugkritso-png/webswither/HEAD/server/deploy/install.sh | sudo bash
   ```

3. เมื่อเสร็จ สคริปต์จะแสดงค่า `wss://…/?token=…` — นำไปใส่ช่อง **Stream Gateway** ใน WebMix
   (ปุ่มตั้งค่า → แท็บการสตรีม) แล้วกด STREAM ได้เลย

สคริปต์จะติดตั้ง Docker, สร้างรหัสลับ (token) แบบสุ่ม และใช้ **Caddy** ขอใบรับรอง HTTPS ให้อัตโนมัติ
ถ้าไม่มีโดเมน จะใช้ `<IP>.sslip.io` ให้เอง ถ้ามีโดเมนของตัวเอง ให้ชี้ A record มาที่ IP ของเซิร์ฟเวอร์แล้วรัน:

```bash
curl -fsSL https://raw.githubusercontent.com/jugkritso-png/webswither/HEAD/server/deploy/install.sh | sudo DOMAIN=live.example.com bash
```

การดูแลหลังติดตั้ง (ไฟล์อยู่ที่ `/opt/webmix-gateway/server/deploy`):

| ต้องการ | คำสั่ง |
|---|---|
| ดูค่า Gateway URL อีกครั้ง | `sudo cat /opt/webmix-gateway/server/deploy/gateway-url.txt` |
| ตรวจสถานะ | เปิด `https://โดเมน/` ในเบราว์เซอร์ ต้องเห็น `WebMix Stream Gateway: OK` |
| ดู log | `cd /opt/webmix-gateway/server/deploy && sudo docker compose logs -f gateway` |
| อัปเดตเป็นเวอร์ชันล่าสุด | รันคำสั่งติดตั้งเดิมซ้ำ (token และโดเมนเดิมยังอยู่) |
| เปลี่ยน token | ลบบรรทัด `STREAM_TOKEN=` ใน `.env` แล้วรันคำสั่งติดตั้งซ้ำ |
| เปิดพอร์ต UDP สำหรับรับ SRT เพิ่ม | รันคำสั่งติดตั้งซ้ำโดยใส่ `SRT_PORTS=9000-9019` หน้า `bash` |
| ถอนการติดตั้ง | `cd /opt/webmix-gateway/server/deploy && sudo docker compose down -v && sudo rm -rf /opt/webmix-gateway` |

### รันเองแบบไม่ใช้ Docker

```bash
# ต้องมี Node.js 18+ และ ffmpeg ติดตั้งในเครื่องที่รัน Gateway
cd server
npm install
STREAM_TOKEN=รหัสลับของคุณ PORT=8080 npm start
```

ในหน้า WebMix กดปุ่มตั้งค่า (ไอคอนแถบเลื่อน) → แท็บ **การสตรีม**:

- Stream Gateway ใส่ `wss://โดเมนของคุณ:8080/?token=รหัสลับของคุณ`
- กด **เพิ่มปลายทาง** ตามจำนวนช่องที่ต้องการ เลือกแพลตฟอร์ม (YouTube / Facebook / Twitch / RTMP อื่น ๆ)
  แล้วใส่ Stream Key ของแต่ละช่อง (ช่องที่ติ๊กไว้คือช่องที่จะเริ่มเมื่อกด “เริ่มทั้งหมด”)
- กด **STREAM** ที่แถบด้านบน (หรือแถบสถานะ STREAM ด้านล่าง) เพื่อเปิดแผงปลายทาง:
  - กด **เริ่ม** ที่ช่องใดก็ได้ เพื่อไลฟ์เฉพาะช่องนั้น แล้วค่อยเริ่มช่องอื่นเพิ่มทีหลังได้
  - กด **เริ่มทั้งหมด** เพื่อเริ่มทุกช่องที่ติ๊กไว้พร้อมกัน
  - กด **หยุด** ทีละช่อง หรือ **หยุดทั้งหมด** — เมื่อหยุดช่องสุดท้าย ระบบจะตัดการเชื่อมต่อ Gateway ให้เอง
- ความละเอียด เฟรมเรต และบิตเรตตั้งได้ในแท็บ **เอาต์พุต**

หมายเหตุ

- หน้าเว็บที่เปิดผ่าน HTTPS (เช่น GitHub Pages) ต้องใช้ `wss://` ดังนั้นควรวาง Gateway ไว้หลัง reverse proxy ที่มี TLS
  (เช่น Caddy / Nginx) — ถ้าทดสอบในเครื่องตัวเองผ่าน `http://localhost` ใช้ `ws://localhost:8080` ได้
- ควรตั้ง `STREAM_TOKEN` ทุกครั้งที่เปิด Gateway ให้เข้าถึงจากอินเทอร์เน็ต ไม่เช่นนั้นใครก็ใช้เครื่องคุณส่งสตรีมได้

## ใช้ Gateway ร่วมกันหลายคน และการเฝ้าระวัง

**Token แยกรายคน** — ให้แต่ละคน/แต่ละทีมมี token ของตัวเอง ยกเลิกหรือออกใหม่ได้ทันทีโดยไม่กระทบคนอื่น

```bash
cd /opt/webmix-gateway/server/deploy
docker compose exec gateway node stream-gateway.js user add somchai                 # แสดง token ครั้งเดียว
docker compose exec gateway node stream-gateway.js user add newsroom --streams 2 --destinations 4 --srt 3
docker compose exec gateway node stream-gateway.js user list
docker compose exec gateway node stream-gateway.js user token somchai               # ออก token ใหม่ (อันเก่าใช้ไม่ได้ทันที)
docker compose exec gateway node stream-gateway.js user disable somchai             # ระงับ (enable เพื่อเปิดคืน, remove เพื่อลบ)
```

- ผู้ใช้ใส่ `wss://โดเมน/?token=<token ของตัวเอง>` ในหน้าตั้งค่าของ WebMix
- โควตาเริ่มต้นต่อคน: สตรีมพร้อมกัน 1, ปลายทาง 6, SRT ขาเข้า 2 — เกินแล้ว WebMix แสดงเหตุผลเป็นภาษาไทย
- เซิร์ฟเวอร์ทั้งเครื่องสตรีมพร้อมกันได้ `MAX_STREAMS` สตรีม (install.sh ตั้งให้ = จำนวนคอร์ ÷ 2) กันเครื่องรับไม่ไหวจนทุกคนกระตุก
- ไฟล์ผู้ใช้เก็บเฉพาะค่า hash ของ token และอยู่ใน volume จึงไม่หายเมื่ออัปเดต
- `STREAM_TOKEN` เดิมคือผู้ดูแลระบบ (ไม่จำกัดโควตาต่อคน)
- ใส่ token ผิดเกิน 10 ครั้งใน 5 นาที IP นั้นจะถูกบล็อก 15 นาที
- การเชื่อมต่อที่ค้าง (เน็ตหลุดแบบไม่ปิด) ถูกตัดภายใน ~30 วินาที และถ้าคนเดิมเชื่อมต่อกลับมา ระบบแทนที่ของเก่าให้ทันที ไม่ติดโควตา

**หน้าสถานะผู้ดูแล** — `https://โดเมน/admin?token=<STREAM_TOKEN>` แสดง CPU, หน่วยความจำ, สตรีมของทุกคน
(สถานะแต่ละปลายทาง, ความเร็วการเข้ารหัส), SRT ขาเข้า และแจ้งเตือนล่าสุด อัปเดตทุก 3 วินาที (ไม่แสดง Stream Key)

**แจ้งเตือนเข้ามือถือ** — รัน install.sh ซ้ำพร้อมช่องทางที่ต้องการ:

```bash
curl -fsSL https://raw.githubusercontent.com/jugkritso-png/webswither/HEAD/server/deploy/install.sh | \
  sudo ALERT_WEBHOOK=https://discord.com/api/webhooks/... bash
# หรือ Telegram
curl -fsSL https://raw.githubusercontent.com/jugkritso-png/webswither/HEAD/server/deploy/install.sh | \
  sudo TELEGRAM_BOT_TOKEN=123:ABC TELEGRAM_CHAT_ID=-100123 bash
```

แจ้งเมื่อ: ปลายทางหลุดนานเกิน 20 วินาที (และแจ้งอีกครั้งเมื่อกลับมา), สตรีมที่กำลังไลฟ์หลุดจาก WebMix และไม่กลับมาใน 30 วินาที,
เข้ารหัสไม่ทันเวลาจริง (ภาพจะกระตุก), สัญญาณ SRT ขาเข้าหาย, CPU/หน่วยความจำของเซิร์ฟเวอร์เต็ม, เซิร์ฟเวอร์เต็มจนมีคนเริ่มสตรีมไม่ได้
และมีคนพยายามเดา token — ใช้ได้กับ Discord, Slack, Google Chat (webhook) และ Telegram

**Prometheus / Grafana** — `GET /metrics` (ส่ง `Authorization: Bearer <STREAM_TOKEN>` หรือตั้ง `METRICS_TOKEN` แยก)

## ส่งสัญญาณด้วย SRT

SRT (Secure Reliable Transport) ทนอินเทอร์เน็ตกระตุก/แพ็กเก็ตหายได้ดีกว่า RTMP และเข้ารหัส AES ได้
เหมาะสำหรับส่งเข้า **vMix, OBS, Wowza, Haivision, SRT Live Server, MediaMTX** หรือห้องควบคุม/สถานีปลายทาง

1. ตั้งค่า → แท็บ **การสตรีม** → **เพิ่มปลายทาง** → เลือกแพลตฟอร์ม **SRT**
2. ใส่ `srt://host:port` ของฝั่งรับ (ฝั่งรับต้องเปิดโหมด **listener**)
3. ใส่ **Stream ID** (ถ้าฝั่งรับต้องการ เช่น SRT Live Server / MediaMTX ใช้ระบุชื่อสตรีม)
4. ใส่ **รหัสผ่านเข้ารหัส** 10–64 ตัวอักษร (ถ้าฝั่งรับตั้งไว้ — ต้องตรงกันทั้งสองฝั่ง)
5. เลือก **Latency**: ในเครือข่ายเดียวกัน 120–200 ms · ผ่านอินเทอร์เน็ต 500–2000 ms (ยิ่งสูงยิ่งทนเน็ตกระตุก แต่ดีเลย์มากขึ้น)

ส่ง SRT ร่วมกับ RTMP (เช่น YouTube) ได้ในการไลฟ์ครั้งเดียวกัน — Gateway ส่ง SRT เป็น MPEG-TS แบบ caller
จึงไม่ต้องเปิดพอร์ตเพิ่มบนเซิร์ฟเวอร์ Gateway (เปิดพอร์ต UDP ที่ฝั่งรับแทน)

## รับสัญญาณ SRT เข้ามาเป็น Input (จาก OBS / vMix / encoder / กล้อง)

เบราว์เซอร์รับ SRT เองไม่ได้ Stream Gateway จึงรับแทนแล้วส่งต่อให้ WebMix ผ่าน WebSocket
(วิดีโอ H.264 ส่งต่อโดยไม่เข้ารหัสใหม่ จึงแทบไม่ใช้ CPU แม้เป็น 4K · ถ้าเป็น H.265/HEVC จะแปลงเป็น H.264 ให้อัตโนมัติ)

1. ตั้งค่า Stream Gateway ให้เรียบร้อยก่อน (ดูหัวข้อด้านบน)
2. กด **เพิ่ม Input → สัญญาณ SRT** แล้วเลือกวิธีรับ:
   - **รอรับ (ผู้ส่งเชื่อมต่อเข้ามา)** — เลือกพอร์ต (9000–9009) ระบบจะแสดงค่าที่ต้องใส่ในโปรแกรมผู้ส่ง เช่น OBS:
     `srt://โดเมน-gateway:9000?mode=caller&latency=500000`
   - **ดึงจาก SRT Server** — ใส่ `srt://host:port` ของต้นทาง (ต้นทางเป็นโหมด listener) และ Stream ID ถ้ามี
3. ใส่รหัสผ่านเข้ารหัสและ Latency ให้ตรงกับฝั่งผู้ส่ง แล้วเริ่มส่งภาพ — ภาพและเสียงจะขึ้นใน Input นั้นอัตโนมัติ

- ต้องเปิดพอร์ต **UDP 9000–9009** ในไฟร์วอลล์ของผู้ให้บริการเซิร์ฟเวอร์ (สคริปต์ติดตั้งเปิดใน ufw และ Docker ให้แล้ว)
  เปลี่ยนช่วงพอร์ตได้ด้วย `SRT_PORTS=9000-9019` ตอนรันคำสั่งติดตั้ง
- ถ้าผู้ส่งหยุดหรือหลุด Input จะขึ้น WAITING / NO SIGNAL และรับสัญญาณใหม่เองเมื่อผู้ส่งกลับมา
- Input SRT ถูกจำไว้และเชื่อมต่อใหม่ให้อัตโนมัติเมื่อเปิดหน้าเว็บครั้งถัดไป
- ใช้ได้บน Chrome, Edge, Firefox, Safari (คอมพิวเตอร์และ iPad) — iPhone ต้องเป็น iOS 17.1 ขึ้นไป
- ถ้าส่งจาก OBS และตั้งรหัสผ่าน ควรใช้รหัสที่ไม่มีอักขระ `& # ?` หรือช่องว่าง (OBS อ่านรหัสจาก URL)

## บันทึกวิดีโอ

ปุ่ม **● REC** เลือกฟอร์แมตที่เบราว์เซอร์รองรับให้อัตโนมัติ (Chrome/Firefox ได้ `.webm`, Safari ได้ `.mp4`)
ที่ 1440p/4K ระบบจะเลือก H.264 (`.mp4`) ก่อนถ้าเบราว์เซอร์รองรับ เพราะใช้ชิปเข้ารหัสในเครื่องได้และเบากว่า VP9 มาก

ไฟล์ถูกเขียนลงดิสก์ระหว่างบันทึก (ไม่เก็บใน RAM) จึงบันทึกนานหลายชั่วโมงได้:
- Chrome / Edge: เลือก **โฟลเดอร์บันทึกวิดีโอ** ที่ ตั้งค่า → เอาต์พุต แล้วไฟล์จะถูกเขียนลงโฟลเดอร์นั้นโดยตรง
- ถ้าไม่ได้เลือกโฟลเดอร์ ไฟล์จะถูกเขียนลงพื้นที่ชั่วคราวของเบราว์เซอร์บนดิสก์ แล้วดาวน์โหลดเมื่อกดหยุด

ไฟล์ WebM จาก MediaRecorder ปกติไม่มีความยาวและไม่มีดัชนี จึงลากแถบเวลาไม่ได้ — WebMix เพิ่ม Duration, Cues และ SeekHead
ให้ระหว่างเขียนไฟล์ (ไม่ต้องโหลดทั้งไฟล์เข้า RAM) ไฟล์ที่ได้จึงแสดงความยาวและเลื่อนหาตำแหน่งได้ทั้งในเบราว์เซอร์, VLC และโปรแกรมตัดต่อ

## บันทึกโชว์

โชว์ = Input ทั้งหมด (ลำดับ ชื่อ ข้อความ), Program/Preview, มิกเซอร์เสียง (ระดับ, Mute, AFV, EQ/คอมเพรสเซอร์/ดีเลย์), กราฟิก และ preset ป้ายชื่อ

- **บันทึกอัตโนมัติ** ในเบราว์เซอร์ทุกครั้งที่มีการเปลี่ยนแปลง — รีเฟรช, เบราว์เซอร์ปิดไปเอง หรือเปิดเครื่องใหม่ โชว์กลับมาครบ
- ไฟล์วิดีโอ/รูปเก็บสำเนาไว้ในพื้นที่ของเบราว์เซอร์ จึงไม่ต้องเลือกไฟล์ใหม่ · กล้องและไมค์เปิดอุปกรณ์เดิมให้เอง (ถ้ารหัสอุปกรณ์เปลี่ยนจะหาจากชื่อ)
- กล้องมือถือที่เคยเชื่อมต่อจะกลับเข้าช่องเดิมเอง · แชร์หน้าจอ/ไฟล์ที่หาไม่พบจะแสดงปุ่ม 🔗 บนการ์ดเพื่อเชื่อมต่อใหม่
- กราฟิกจะไม่ขึ้นจอเองหลังรีเฟรช (ป้องกันภาพหลุดออกอากาศ)
- ปุ่ม **โฟลเดอร์** ด้านบน: ตั้งชื่อโชว์, **บันทึกเป็นไฟล์** `.webmix.json`, **เปิดไฟล์โชว์** และ **เริ่มโชว์ใหม่**
  ไฟล์โชว์ไม่รวมตัวไฟล์วิดีโอ/รูป (เปิดบนเครื่องอื่นแล้วกด 🔗 เพื่อเลือกไฟล์) และมี Stream Key/รหัส SRT เฉพาะเมื่อเลือก “จำ Stream Key” ไว้
- **Preset ป้ายชื่อ** ในแท็บ TITLE: กด “+ บันทึกป้ายนี้” แล้วแตะเพื่อสลับชื่อ/ตำแหน่ง/สีระหว่างรายการ

## ความทนทานระหว่างไลฟ์

- ถ้าการเชื่อมต่อกับ Stream Gateway หลุด (เน็ตสะดุด, Gateway รีสตาร์ท หรือค้าง) ปุ่มจะขึ้น **RECONNECTING**
  และระบบจะเชื่อมต่อใหม่ (1 → 2 → 4 → 8 → 10 วินาที) แล้วเริ่มปลายทางที่ไลฟ์อยู่ให้เอง โดยไฟ ON AIR และเวลาออกอากาศยังเดินต่อ
- ปลายทางที่หลุดเฉพาะช่องจะลองใหม่ทุก 5 วินาที, ไม่มีสัญญาณจาก Gateway เกิน 8 วินาทีถือว่าค้างและเชื่อมต่อใหม่

## โครงสร้างโค้ด

ไม่ต้อง build — เปิด `index.html` ได้ตรง ๆ ไฟล์ JavaScript ทั้งหมดเป็นสคริปต์ธรรมดาที่โหลดตามลำดับและใช้ `window.WebMix` ร่วมกัน

| ไฟล์ | หน้าที่ |
|---|---|
| `assets/js/core.js` | ตัวช่วยทั่วไป, localStorage, toast, กันจอดับ, ค่าการเชื่อมต่อ WebRTC |
| `assets/js/draw.js` | วาดแหล่งภาพที่สร้างเอง (Bars, Slate, นาฬิกา, NO SIGNAL, ป้ายชื่อ, Title) |
| `assets/js/keyer.js` · `assets/js/gpu.js` | คีย์ฉากเขียวด้วย GPU · ระบบวาดภาพด้วยการ์ดจอ (WebGL) |
| `assets/js/storage.js` | IndexedDB และ OPFS (ไฟล์ของโชว์) |
| `assets/js/caller.js` | หน้ากล้องมือถือและหน้าแขกรับเชิญ |
| `assets/js/multiview.js` · `assets/js/manual.js` | Multiview · คู่มือและคีย์ลัดในแอป |

| `assets/app.js` | สตูดิโอ: Input, การสลับภาพ, Overlay, เสียง, บันทึก, สตรีม, โชว์ |
| `server/` | Stream Gateway (`stream-gateway.js`), ผู้ใช้ (`users.js`), การเฝ้าระวัง (`monitor.js`), ชุดติดตั้ง (`deploy/`) |

## การใช้งาน 4K

- ตั้งค่า → แท็บ **เอาต์พุต** → เลือก **3840 × 2160 (4K UHD)** ระบบจะใส่บิตเรตแนะนำให้ (4K30 ≈ 25000 kbps, 4K60 ≈ 37500 kbps)
- เพิ่มกล้องแล้วเลือกความละเอียด **4K UHD** — ถ้ากล้องรองรับไม่ถึง ระบบจะแจ้งความละเอียดที่ได้จริง และการ์ดของแต่ละ Input แสดงความละเอียดจริงเสมอ
- กล้องมือถือ: แตะปุ่ม **HD / FHD / 4K** บนหน้าจอมือถือเพื่อเลือกคุณภาพที่ส่งเข้าสตูดิโอ
- คอมพิวเตอร์ที่เปิด WebMix ควรมี CPU 8 คอร์ขึ้นไปหรือการ์ดจอแยก และอินเทอร์เน็ตขาขึ้นอย่างน้อย 1.5 เท่าของบิตเรต (4K30 ≈ 40 Mbps)
- YouTube รับได้ถึง 4K · Facebook และ Twitch รับสูงสุด 1080p (ระบบจะเตือนเมื่อเริ่มสตรีม 4K ไปปลายทางเหล่านี้)
